---
description: (メンテナー向け) 要トリアージの Issue をトリアージする
argument-hint: [Issue の番号 (省略すると要トリアージのものすべて)]
---

`要トリアージ` が付いている Issue をトリアージする。番号があれば ($ARGUMENTS) その Issue だけ、無ければ `要トリアージ` の付いた開いている Issue すべて。

このコマンドはメンテナーだけが使う。

## 1 件ずつ見ること

- 何が起きているか・何をしてほしいかを 1〜2 文にまとめる
- 情報が足りるか。足りなければ、何を聞けばよいか (版・打ったキー・アプリなど)
- 再現できるか。誤判定は `dotnet run --project src/Meltype.Core.Tests -- --repro <打ったもの> enter` で確かめる
- 重複していないか (似た Issue を検索する)
- ラベル: 種類 (不具合・誤判定・辞書・提案)、OS、優先度 (止まる・入力できない・文字が消えるなら `優先: 高`)
- 方針に合うか (CONTRIBUTING.md の「大事にすること」「やらないこと」、AGENTS.md の設定の決まり)

## 分け方

- **進める**: ラベルを整え、`要トリアージ` を外す案を出す。小さくて手順がはっきりしていれば good first issue の候補にする (`/GFI-triage`)
- **情報待ち**: 聞くことをコメントの案にし、`情報待ち` を付ける案を出す
- **重複**: 元の Issue の番号を書く
- **方針に合わなそう**: 理由を添えて一覧にするだけにする

## 閉じない

方針に合わなそうなもの・重複は、**一覧に出すだけで閉じない**。閉じるのは、メンテナーが「閉じて」と明示したものだけ。閉じるときは、理由と、どうすれば進められるか (Issue での相談など) をコメントに書き、`state_reason` を付ける。

ラベルの付け外し・コメントも、一覧を見せてメンテナーが「やって」と言ってからする。

## 出すもの

番号・タイトル・まとめ・分け方・付けるラベル・コメントの案を表にする。最後に「方針に合わなそうなもの」を別の一覧にする。
