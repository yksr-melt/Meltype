argument-hint: <PR か Issue の番号>

#$ARGUMENTS (PR か Issue) を読み、メンテナー向けに短く説明する。コメントもすべて読む。PR なら変更も読む。

このコマンドは読むだけで、GitHub には何も書かない。

## 出すもの

1. **何の話か**: 何が困っていて、何をしようとしているか (2〜3 文)
2. **今どうなっているか**: 議論の流れ、だれが何を言っているか、止まっている理由
3. **現実的か**: 作る量・難しさ・確かめ方。ほかの OS やフロントにも要るか、実機でしか確かめられないか
4. **方針に合うか**: CONTRIBUTING.md の「大事にすること」「やらないこと」と AGENTS.md (設定は最小限、OS ごとの差を作らない など) に照らして。合わないなら、どこが合わないか
5. **おすすめ**: 進める / 直してもらう / 引き取る (`/8pr`) / 情報を聞く / 閉じる候補、のどれかと、その理由

長くしない。全体で画面 1 つに収める。
