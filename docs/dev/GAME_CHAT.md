# ゲームのチャット欄の判定

Meltype キーボードが、ゲームでチャット欄が開いている間だけキーを受け持ち、閉じている間は移動のキー (WASD) をそのままゲームに通す仕組み。
OS の入力欄の情報 (UI Automation・キャレット) はゲームのチャット欄に出てこないので、IME の入力コンテキストが前面のウィンドウに結び付いているかを手がかりにする。
利用者の説明は [USAGE.md](../USAGE.md)。

## 判断の流れ

| 段階 | 場所 | 内容 |
| --- | --- | --- |
| 事実を読む | `KeyboardFront.PollSystemIme` | 100 ms ごとに前面のウィンドウの既定の IME ウィンドウへ `WM_IME_CONTROL` で変換モードと開閉を聞く。読めたとき、変換モードが 0 でなければ結び付いている |
| ゲートを通す | `KeyboardFront.SetImeContext`・`_detachedSeenIn` | 外れているのを一度見たウィンドウだけ、結び付いたことを `ImeTrait.ImeContext` として送る。読めなかったときは何も判断しない |
| 判断する | `ImeSession.IsGameChat`・`IsGame`・`IsActive` | ゲーム (アプリ別設定の種類か、「ゲームでは止める」) で `ImeContext` があればチャット欄が開いている。受け持って日本語にする。閉じたら止めて英数に戻す |

Meltype IME・macOS・Linux のフロントは `ImeContext` を送らないので、動きは変わらない。

## フレームワークごとの挙動

入力欄がないときに IME の入力コンテキストを外すかは、フレームワークで違う。コードを読んで確かめた。

| フレームワーク | 外すか | 根拠 |
| --- | --- | --- |
| Unity (VRChat) | 外す | 実測。外れている間の変換モードは 0、結び付くと 25。Esc を押してから 0 になるまで 35〜146 ms |
| Godot | 外す | `display_server_windows.cpp`: ウィンドウを作るときに外し、入力欄にフォーカスがあるときだけ `window_set_ime_active` で結び付ける。実測でも、入力欄に入ると変換モード 25・キャレット有り、出ると 0 |
| winit (Rust: Bevy など) | 外す | `ime.rs`: `set_ime_allowed(false)` で `ImmAssociateContextEx(..., NULL, IACE_CHILDREN)`。ゲームが呼ぶかは別 |
| SDL3 | 外せる | `SDL_windowskeyboard.c`: `SDL_StopTextInput` で `ImmAssociateContext(hwnd, 0)`。呼ばないゲームは外さない |
| Minecraft 26.3 (SDL3) | 外さない | 実測。チャット欄の開閉に関係なく、変換モードは常に 25 か 9。クラス名は `SDL_app` で、ゲームとは判定されない |
| GLFW (Minecraft 26.2 まで・LWJGL3・raylib など) | 外さない | `src` に `ImmAssociateContext` がない。常に既定のコンテキストのまま |
| Unreal | 未確認 | |

外さないゲームは変換モードが常に 0 でないので、ゲートがないと、ゲームでは常にチャット欄が開いている扱いになり、移動のキーまで取ってしまう。
その場合は今までどおり止まる。そうしたゲームでチャットを打つには、アプリ別設定で種類を「ゲーム」にして「入力欄とみなす」を ON にする (#2403)。

## 値の読み方

- 変換モードが 0 でない値は、設定や IME のモードで変わる (日本語 IME の既定は 25、IME を ON にすると 9 など)。値の一致ではなく、0 かどうかで見る。
- 問い合わせは、相手が忙しいとタイムアウトする (Minecraft・タスクバーなどで確認)。タイムアウトは外れたこととは別なので、判断しない。
- 100 ms ごとの問い合わせは、1 回 0.04〜0.13 ms の CPU (Claude Desktop・Discord・Godot で測定)。Godot では、相手の描画ループが処理を拾うまで 11 ms ほど待つが、待つのは問い合わせのスレッドだけ。

## 検討して取らなかった案

- **OS からチャット欄を読む (UI Automation・キャレット)**: Unity・GLFW のチャット欄は OS から見えない (#2248)。
- **変換モードが 25 のとき**: 25 は IME の既定値で、外さないアプリ・ゲームでも常に 25。IME のモードが変わると 25 以外になる。
- **Esc・長押しで英数に戻す**: 閉じたことを知らせないゲームの代替策 (#2248・#2403)。外すゲームは、外れたことで閉じたと分かる。

## Meltype IME (TSF)

外れると、TIP に document focus の `null` が届く (Godot で、変換モードが 0 になる 47 ms 前)。外れている間は `OnTestKeyDown` の記録がなかったが、その間にキーを押したかは未確認。
ちらつき (`あり` → `null` → `あり` が 80 ms 以内) があり、ウィンドウの切り替え (Alt+Tab) でも `null` が来る。通知の時点では、切り替えと外れたことを区別できない。
VRChat は #539 (署名) のため TIP が読み込まれず、実機で確かめられない。

実装するなら、Meltype キーボードと同じ判定を Meltype.exe に 1 か所置き、`TipServer` が TSF の入力欄にも `ImeContext` を足す。TIP は外れている間は呼ばれないので、呼ばれた時点でゲートを通っていれば、チャット欄が開いている。
