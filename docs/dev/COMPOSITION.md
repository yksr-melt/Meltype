# 入力と変換の処理

フロントは `ImeHost` に OS の事実を送り、応答を入力欄に適用する。`ImeSession` が入力欄を管理し、未確定入力の出来事を `CompositionController` に渡す。`Composition` の中の処理をフロントから直接呼ばない。

## 責務

| 型 | 受け持つもの |
| --- | --- |
| `CompositionController` | 出来事の入口。1 回分の出力を始め、処理と表示を呼び、応答を返す |
| `CompositionKeys` | キーの割り当て、入力・変換中の操作、かな配列 |
| `CompositionDirectInput` | 英数状態の打鍵をすぐアプリへ通し、ローマ字と分かったら日本語入力へ移す |
| `CompositionConversion` | 読みから文節・候補を作る、候補を追加する、文節の区切りを変える |
| `CompositionCommit` | 確定する文字を作る、学習する、直前の確定を文脈に合わせて修正する |
| `CompositionPresentation` | 表示、候補の注記、予測の一覧を作る |
| `CompositionSpelling` | 書き間違いの提案・修正、利用者が直した判定の記録 |
| `CompositionContext` | キャレットの前後と直前の確定から、判定・変換・学習の文脈を作る |
| `CompositionLifecycle` | 入力の開始・終了・取消、モードと文脈の破棄 |
| `CompositionRefresh` | 背景の答えを反映するか決め、利用者の操作を維持する |

各処理は `CompositionController` を呼び戻さない。キーの処理は変換・確定・表示を呼べるが、変換・確定・表示はキーの処理を呼ばない。表示は確定を呼ばず、確定と表示で共有する表示文字列は `CompositionPresentation.CurrentDisplay` で作る。学習は変換処理を呼ばず、かな・漢字の有無のような文字の判定は `Libraries.Chars` を使う。

状態は `ImeHost` が持つ `ImeSessionState.Composition` に置く。処理の class 自身には入力欄の状態を持たせない。文節・予測・確定し直せる語の記録は `CompositionModels.cs` にあるデータの型で渡す。

## 状態の寿命

同じ入力欄でも、未確定入力・直接入力の判定・直前の確定・物理キーでは寿命が違う。まとめて初期化すると、確定後の文脈や押したままの親指キーを失う。開始・終了時の処理は `CompositionLifecycle` に集め、操作中の候補や文節はそれぞれの処理が更新する。

| 場面と処理 | 消す・更新するもの | 保つもの |
| --- | --- | --- |
| 新しい入力を開始 (`BeginComposition`) | 入力の秘匿属性、前の候補の控え、F6〜F10・Esc の記録を初期化し、文字列の設定を反映 | 直前の確定の文脈、押したままのキー |
| 確定する文字を作り終えた (`FinishText`) | 読みと変換中の文節 | 直前の確定の文脈。通常の確定は続けてその記録を更新する |
| 再変換を取り消す (`ClearComposition`) | 読み・変換中の文節・元の選択範囲の記録 | 入力欄の確定済みの文字。置き換えを返さない |
| 出来事の処理が終わる (`EndEvent`) | 入力が空なら再変換の記録と押したキーを消す | 入力中、または親指キーを押したままなら保持する |
| 直接入力の判定をやめる (`ClearHeld`) | 判定中の英字と、アプリに通した文字の記録 | すでにアプリへ通した文字。削除が必要なら呼ぶ側が明示する |
| フォーカス移動後など (`ResetContext`) | 直前の確定の文字・言語と、確定し直せる語の履歴 | 自分の確定直後にアプリの古い文字を信じないための時刻 |
| キャレットや確定済みの文字が外から変わる (`ForgetLastCommit`) | 直前の確定の文脈・履歴・時刻と、出力中の確定の控え | 現在の未確定入力 |
| パスワード欄などへ移る (`CancelPending`) | 未確定入力、直接入力の判定、文脈、候補の控え、予測・ライブ変換のキャッシュ、押したキーとかな配列の状態 | 確定済みの文書。未確定入力を確定せずに捨てる |

予測は打った文字と表示モードのキーを照合して使う。ライブ変換のキャッシュは読み・文脈・学習の版などをキーにして使う。表示に使えるかは、単にキャッシュが残っているかでは決めない。

確定し直しで消す数と入れ直す文字は、`CorrectPreviousCommit` の戻り値として同じ確定処理の中だけで使う。入力欄の状態に保留しない。

## 遅れて届く変換結果

通知そのものには、今の入力へそのまま適用する文字列を持たせない。今の読み・文脈で変換エンジンのキャッシュを問い合わせ直す。

1. 未確定入力が空なら、表示を再開しない。
2. 再変換中・文節の区切りを操作済み・文全体の別案を選択済みなら、開いている変換を作り直さない。
3. `BuildConversion` で新しい文節・候補を別に作る。この段階では開いている `Conversion` を置き換えない。
4. `Merge` が古い変換と新しい変換だけを比較する。新しい情報がない場合と、候補・文節を操作した後に文節の並びが変わる場合は、古い変換を返す。
5. 文節の読みと並びが同じなら、選び直した候補と選択中の文節を引き継ぐ。候補に付随する英訳・学習対象外の記録も引き継ぐ。
6. 採用が決まった後に `state.Conversion` を置き換え、表示を作り直す。予測を選んでいる間はその選択を保つ。

`Merge` は前の変換を書き換えず、表示や変換エンジンにも触れない。候補を作る途中や、採用しない答えで、現在の変換を一時的に消してから戻す処理をしない。

## 確認

`BackgroundConversionTests` は、遅れた答え、選択した候補・文節・予測の維持、確定・取消・全削除の後の通知を確かめる。`CompositionTests` と `ImeContractTests` は、確定・取消・再変換・フォーカス移動を含む打鍵と応答を確かめる。構造の整理では、これらの操作結果を変えない。
