03 構成

確定

対応環境

項目 値

CPU arm64-v8a（実機）、x86_64（エミュレーター）
言語 Kotlin（Android UI・QWERTY入力フロント）、C#（共有Meltype.Core、NativeAOT）、C++（JNI・Mozc）
ビルド Gradle（Kotlin DSL）、.NET NativeAOT、Android NDK
リポジトリ 本家のAndroid開発元 ninjin0802/Meltype:android に対するFork上の機能追加ブランチ
アプリの表示名 Meltype
アプリ ID io.github.ninjin0802.keyboard（公開前に変えてよい。変えると別アプリ扱いになり学習データは引き継がれない）

モジュール

Gradleモジュールはappとmozcの2つ。入力判断は共有C# Coreに一本化し、Kotlinの旧入力エンジンは削除した。

モジュール 役割 Android への依存
app キーボード本体。QWERTY・記号配列の描画、タッチ判定、候補バー、入力欄とのやり取り、導入画面 あり
mozc Mozc を呼び出す層。変換エンジンの本体（libmozc.so）と辞書（mozc.data）を同梱する あり
src/Meltype.Core/（共有）QWERTYローマ字入力の日英自動判別、未確定文字と候補の管理C#（Android向けNativeAOT出力）
app/src/main/cpp/C# NativeAOTライブラリとのJNI接続、Kotlinからのコールバックあり（NDK）

依存の向き

日本語QWERTY: app ──→ JNI ──→ C# Meltype.Core (NativeAOT)
                                   └──→ Mozc変換コールバック（端末内）
英字QWERTY・数字記号・変換無効欄: app ──→ InputConnection
  • app は入力欄の事実とキーを共有Coreへ送り、その応答を入力欄に適用する。
  • mozc は共有Coreから要求されたかな漢字変換を端末内で実行する。
  • 変換無効の入力欄では、キーの文字を直接入力する。12キー・フリックの実装は含まれない。

入力判断を共有Coreに一本化することで、デスクトップ版との二重実装による挙動差を避ける。Coreが利用できない場合は別のローマ字エンジンへ切り替えず、退避用IME選択画面を出す。

処理の流れ

  1. 利用者がQWERTYのキーを押すと、app がAndroidのキー操作と入力欄の状態を取得する。
  2. 日本語QWERTYではJNI経由でC# Coreへ出来事を送る。変換が必要ならCoreからMozcを呼ぶ。
  3. Coreが返した指示をアダプターが入力欄と候補バーに適用する。
  4. 英字QWERTY・数字記号・変換無効欄では、必要に応じて文字を直接入力する。
  5. Coreの初期化・応答が失敗した場合は未確定文字を保護し、Android標準のIME選択画面に退避できる。

C# CoreはAndroidの入力欄に直接触れない。入力欄への書き込みはappのInputConnectionアダプターが行う。詳しくは08。

スレッド

  • キーの描画とタッチの処理は、画面のスレッドで行う。
  • 変換は時間がかかることがあるので、専用のスレッド1本で順番に行う。
  • 変換の結果が返ったとき、その間に読みが変わっていたら、その結果は捨てる。入力欄が切り替わっていた場合も捨てる。

キーボード画面の作り方

Jetpack Compose は使わず、独自の View で描く。キーボードは押してからの反応の速さが最も大事で、独自 View のほうが軽く、IME での実績も多い。導入画面も同じ理由で通常の View で作り、依存を増やさない。
