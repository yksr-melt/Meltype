08 日英自動判別

概要（段階3。着手するときに詳細を詰めて「確定」に上げる）

目的

QWERTY の配列でローマ字を打つと、日本語か英語かを自動で見分ける。

kyouhagoogledekensaku    →  今日はgoogleで検索
ashitanomeetingwotsuika  →  明日のmeetingを追加
I want to go to the park →  I want to go to the park

決まっていること

  • 判別の仕組みは、Meltype の C# のコードを Kotlin に移植して作る。簡易版を自作しない。
  • 移植したものは engine に入れる。かな漢字変換は、フリックと同じ Converter（06）を使う。
  • 土台は、段階1で作ったローマ字配列とローマ字入力（04、05）。段階1では、そこで打った英字をすべてローマ字として扱う。段階3で、そこに判別を足す。英字だけを打ちたいときは、これまでどおり あa で英語の配列に替える。
  • 移植の元にする本家の版は、コミットを1つに固定して記録する。設計時点の最新は 53fafd036b4d06fab7dae9ca0b9ea4eeafbfe976（v1.2.1 の後）。着手するときの最新に更新する。
  • 移植は、本家のテストを先に Kotlin に写し、それが通るように進める。

規模の見積もり

本家の Meltype.Core は約 700KB、テストは約 446KB ある（設計時点）。全部は移植しない。

移植する見込みのもの:

本家の場所 中身
Detection/ ローマ字・かな・英単語の判定、点数付け
Composition/CompositionDetector.cs 打った文字列を日本語と英語の部分に分ける中心
Composition/CompositionText.cs ローマ字からかなへの変換と、未確定文字の組み立て
Composition/ScoredSegmentation.cs、WordJudge.cs、RomajiTypoCorrector.cs 区切りの点数付け、語の判定、打ち間違いの補正
Composition/LanguageMemory.cs、Learning/UserModel.cs 語ごとの日英の学習
dictionaries/ のうち判別に使うもの 英単語、日本語、固有名詞、外来語 など

移植しないもの:

本家の場所 理由
Config/Settings.cs ほか設定まわり Windows の設定画面とアプリごとの設定のためのもの
Input/LineContext.cs、SigilWord.cs、ProtectedSpan.cs エディターやターミナルでのコード入力のためのもの
Snippets.cs、Backup.cs、Corrections.cs、MisspellingDictionary.cs、MeaningDictionary.cs、TranslationDictionary.cs 定型文、バックアップ、書き間違いの指摘、意味や英訳の表示。判別そのものではない
src/Meltype/、native/、mac/、linux/ 各 OS に固有の部分

CompositionController.cs（約 141KB）と MeltypeSession.cs は、キー操作と未確定文字の管理を担う。こちらのアプリは 05 の入力セッションを持っているので、そのまま移植せず、必要な判断だけを取り込む。どこまで取り込むかは着手するときに決める。

着手するときに決めること

  • 上の「移植する見込み」を実際のコードで確かめ、範囲を確定する。
  • 本家の更新を、どの頻度で、どうやって取り込むか。
  • 05 の入力セッションは、読みと打ちかけの英字を持つところまでできている。英語と判別した部分をどう持つか、⇧ で打つ大文字（段階1では、確定してから直接入力する）をどう扱うか。
  • 判別の強さの設定（本家は4段階）を持つか。
