08 日英自動判別

実装済み 日本語QWERTYで利用可能（2026-10-25検証）

適用範囲

日本語QWERTY（ローマ字入力）では、英語・日本語・日英混在を手動切り替えなしで入力できる。従来の「判別は未実装、C#をKotlinに移植する」という設計は採用しない。Windows等と同じC# Meltype.Coreを共有する。

共有Coreによる日英自動判別は日本語QWERTYのみ。英字QWERTY・数字記号および変換無効の入力欄は文字を直接入力する。12キー・フリックは提供せず、Issue #1885 で別途設計する。

実装

  1. AndroidのKeyboardServiceが日本語QWERTYの入力を受ける。
  2. MeltypeCoreHostがJNIのlibMeltypeNative.so（meltype_ime_create / meltype_ime_handle / meltype_ime_destroy）を呼ぶ。デスクトップ版と同じ入力の仕組み（ImeHost）で、キーボード全体で1つ持つ。C# Meltype.CoreはAndroid向けにNativeAOTでビルドする（arm64-v8a/x86_64）。
  3. Androidは入力欄の事実（アプリのパッケージ名、キャレットの前4000字・後ろ20字の文字（Mac・Linuxと同じ。変換中の文字は除く）、選択している文字、パスワード欄・学習しないでほしい欄の印）とキーを出来事のJSONで送る。自分の文字を持たない入力欄（TYPE_NULL）では前後の文字を送らず、前の文字を消せない欄として送る。JSONを作る・読むのはcore/ImeJson.ktだけ。
  4. キーボード自身がCoreのために書き換えた分（確定・変換中の文字・Coreが通したキー）では、キャレットが動いたことにしない。それ以外の移動（タップ、矢印キー、アプリの書き換え）はCaretMovedで伝え、Coreは前の語を確定し直さない。変換中なら、出ている文字のまま確定してCommittedByAppを送る。入力欄を離れるときも、出ている文字のまま確定する。
  5. Coreが日英の判別、未確定文字、変換・予測候補、学習するかを管理する。かな漢字変換には端末内のMozcを使用する。
  6. CoreInputAdapterがCoreの指示をAndroidのInputConnectionへ反映する（確定し直すときはremoveBeforeの長さだけ消して入れる）。CoreCandidateChoicesがCoreの一覧（変換の候補か予測変換の候補のどちらか1つ）の番号を保ち、その一覧だけを候補バーに出す。

Coreが利用できない場合は未確定文字を保護して入力を停止し、Android標準のIME選択画面を直接開ける退避UIを表示する。Kotlinのローマ字エンジンには戻さない。変換を禁止する入力欄では文字を直接入力する（09）。

設定

ライブ変換のオン・オフはCoreの設定で、ほかのOSと同じconfig.json（アプリ専用の領域のmeltype/config.json）に書く。Coreは変わったconfig.jsonを読み直すので、キーボードを閉じなくても次のキーから効く。配列・振動・絵文字・日本語入力時のスペースなどキーボードの画面の設定は、アプリの設定（SharedPreferences）に持つ。

操作

  • QWERTY入力では通常、言語切り替えキーを押す必要はない。
  • 言語配列を明示的に選ぶ場合はスペースを長押しする。記号と数字には専用の2ページ配列を使用する。
  • 入力候補のタップ、句読点・確定操作は未確定文字と変換状態に応じて処理する。

検証

2026-10-25のソースに対し、Android 15（API 35）エミュレーターでInstrumentationの18件すべてが成功。日英の入力、候補選択、訂正候補、設定、Back、システムバーの回帰を含む。Pixel 10 Pro Fold（Android 17）で実機確認済み。CI実行結果。

制限・保留事項

  • Coreによる日英自動判別は日本語QWERTYが対象。12キーの各フリック配列には未提供。
  • 読みから英字を推薦する独立機能（例: ぐーぐる → Google）は未対応（07）。
  • Android版Mozcは検証済みコミットを維持。デスクトップ版との統合は別途検証が必要。
  • 公式AndroidアプリID、リリース署名、各機種の互換性、TalkBackについては本家と調整・追加検証が必要。
